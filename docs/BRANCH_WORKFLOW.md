# Repository Branch & Release Architecture

The **kim-android-apps** repository utilizes an efficient, modular branch-per-application structure designed for high autonomy, modular checkouts, and clean version tracking.

---

## 🌳 Branch Hierarchy

```
                                      kim-android-apps
                                            |
         +----------------------------------+----------------------------------+
         |                                  |                                  |
     [ main ]                          [ gh-pages ]                       [ app/* ]
 Ecosystem Hub & Docs               Public Web Showcase             Modular App Source Trees
 - Master README                    - eliakimrosil.github.io        - app/kim-live-studio
 - apps.json Catalog                  /kim-android-apps/            - app/pan-flip-sear-timer
 - assets/icons/                    - App Landing Pages             - app/glue-set-clamp-sentinel
 - Community & CI                   - Privacy Policies              - app/roast-rest-meat-thermo-sentinel
                                                                    - (28 dedicated branches)
```

### 1. `main` Branch
- **Role**: Flagship repository presentation, master index of all applications, central documentation, issue templates, and catalog metadata.
- **Workflow**: PRs targeting `main` should relate to ecosystem documentation, catalog updates, or global tooling.

### 2. `gh-pages` Branch
- **Role**: Hosts the live GitHub Pages web store and HTTPS privacy policy endpoints for Google Play Developer Console compliance.
- **URL**: [https://eliakimrosil.github.io/kim-android-apps/](https://eliakimrosil.github.io/kim-android-apps/)
- **Workflow**: Automated updates generated by AI App Company or catalog rebuild scripts.

### 3. `app/<slug>` Branches
- **Role**: Complete, isolated native Android source repositories for each individual app.
- **Benefits**:
  - Independent commit history per application.
  - Granular git clones (`git clone --single-branch -b app/<slug> <repo>`).
  - Independent tag versions (e.g. `v1.0.0-<slug>`, `v1.2.0-kim-live-studio`).

---

## 🏷️ Release Tagging Convention

Every application release binary is published to GitHub Releases under an immutable semantic tag:

- **Format**: `v<version>-<app-slug>`
- **Examples**:
  - `v1.2.0-kim-live-studio`
  - `v1.0.0-defrost-safe-meat-prep-sentinel`
  - `v1.0.0-glue-set-clamp-sentinel`
- **Release Assets**: Direct CDN download URLs in the format:
  `https://github.com/eliakimrosil/kim-android-apps/releases/download/v<version>-<slug>/<slug>.apk`
